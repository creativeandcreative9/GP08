# 2026-10-18 遊びの深さを増やすための固定評価

## 目的と点数の意味

「300点以上になるまで改善する」という依頼に対して、前回の100点を何倍かに換算しない。前回の体験基盤100点を残し、これまで十分に作られていなかった三つの品質領域を100点ずつ追加する。合計は400点満点になる。これは設計と検証のための代理指標であって、人間が感じた感動の強さ、満足度、研究で標準化された心理尺度ではない。

**合格条件は総合300点以上、四領域それぞれ70点以上、未解決の重大問題0件。** 基盤については前回の条件（各軸8点以上）も維持する。点数を丸めて合格にせず、改善後に配点・項目・必要な証拠を易しく変更しない。ユーザーの承認待ちにはせず、実装、観察、修正、再検証を続ける。

本書の改善前基準は **`1b3ee3047e36f66e826671edd0cd02a2c77eee3e`**。以下の基準と改善前点数を、追加実装の結果を採点する前に固定した。ソースは作業中のファイルではなく、このコミットの `git show <commit>:<path>` を読んだ。実装予定・担当者の期待・テストの予定には点を与えない。

追加30項目は各10点。**0点：その追加の深さがない、破綻している、または証拠がない。5点：行に記した追加条件の一部が実際に成立するが、範囲・内容・検証が不足。10点：記した内容条件を満たし、対応する実画面・操作と状態の検証がそろう。** ソースしか確認できない実装は最高5点。画面に表示されない保存・分岐・近接判定などは、操作ログと適切な状態／テスト結果を併用する。文章を追加しただけでは、その文章に書いた行動がゲーム内で起きた証拠にならない。

同じ機能が複数領域に関わる場合も、同じ事実だけを繰り返して満点にしない。例えばS4は住人が選択にどう返答するか、R4はその結果を手帳で個別の出来事としてどう読み返せるかを別々に確認する。Wの現地性を、手帳のスクリーンショットだけでは満点にしない。既存の基礎機能だけで追加項目の部分点を作らない。

件数は今回の小規模な街における内容の幅を確かめるための設計上の下限であり、「3人なら人が感動する」といった研究上の閾値ではない。関連研究と適用範囲は [研究ノート](20261018_play_research.md) に記録している。自律性・有能感・関係性、情報の不足を埋める好奇心、明瞭な目標と反応を設計の参考にするが、研究結果をこのゲームの感情効果の実測値に置き換えない。

## 再評価で必要な実操作と記録

1. **人物と選択**：3編を最初から結果まで操作し、2編は両方の分岐を確かめる。別の人物に誤って結果が移らないこと、途中の保留、翌日・再読み込み後の再会も確認する。物語本文の意味と状態検証の両方を残す。
2. **街の発見**：新地点の現在地からの行動、遠隔／壁越しの拒否、6地点と3地域の内容、3テーマの途中と完了、順序違い、時間・天候の差を確認する。位置フックを使った場合は明記し、全経路を歩いた証拠にしない。
3. **振り返り**：新規状態、1日分、2日分、途中の再開、全完了、何も増えなかった日の表示を操作する。人物・選択・場所と表示内容を照合し、PC・スマホ縦横で長い本文と戻る操作を見る。
