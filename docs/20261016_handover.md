確認の手順（CLAUDE.md と同じ）：

1. `npm run typecheck`
2. `npm test`（約 30 件。ヘッドレスは GPU がないので 5〜10 分かかることがある。`--timeout=600000` を付けると安全）
3. `npm run shot -- --query "?view=ref1&gfx=high"` などで画像を撮って目で見る
4. 見た目の変更は `npm run eval -- --tag <日付>_<名前>` で比較カット 5 枚を撮って採点する（`screenshots/` は ignore。モデルが写った画像はコミットしない）

便利な URL パラメータ：

| パラメータ | 意味 |
|---|---|
| `?model=none` | キャラクターなし（`?model=fubuki` 等で指定） |
| `?gfx=high` / `?gfx=low` | 画質（影・SSAO・ブルーム・色調整の有無）。指定なしは GPU があれば high |
| `?view=overview` `street` `platform` `alley` `summit` `ref1`〜`ref5` | 確認用の視点（ref は比較カット） |
| `?life=off` / `?lifeshow=cars` `people` | 人と車を消す／片方だけ |

注意：ヘッドレスの SwiftShader は 1 フレームに数秒かかる。撮影ツールは撮る前に描画ループを止めるので待てば撮れる。`GP08_PORT` で開発サーバーのポートを変えられる（並行作業用）。

### 守るべき約束

- 乱数は `c.rnd()`（種付き）。**引く回数を変えると、それ以降に作られる町の配置が全部ずれる**。比較カットに物が写り込んだら、配置より先にこれを疑う。
- `MeshBatch` に頂点を直接 `push` するときは、`pos`・`nor`・`col` に加えて **`surf` も同じ数だけ** 追加する（ずれると例外になる）。
- 看板の文字は `build.ts` の `labels` に足してからアトラスで使う。
- 比較カットの視線の上には小物を置かない（`furniture.ts` の回廊）。カメラ位置を変えるときは `evalcams.ts` だけを直す。
- モデル、テクスチャ、zip、モデルが写った画像はコミットしない。

## 4. 進め方（並列開発）

このセッションでは、まとめ役（統合・採点・描画とシェーダーの難所）と、分野ごとの作業担当（AI エージェント）に分けて進めた。

- 担当ごとに git worktree（`.claude/worktrees/`、`.git/info/exclude` で除外）を作り、`GP08_PORT` を別にして並行で撮影・テストする。
- 担当は自分のブランチにコミットだけする。まとめ役が `--no-ff` で統合し、テスト・撮影・採点して push する。
- 衝突しやすいのは `src/town/build.ts`（labels と組み立て順）、`src/town/signs.ts`、`src/scene.ts`（import とフック）。
- 注意点：worktree が古いコミットから作られることがある。担当には最初に最新のブランチを取り込ませる（権限の判定で merge が拒否されることがあり、そのときはまとめ役が統合する）。
- 利用上限に当たると担当が止まる。止まった担当は SendMessage で再開できるが、新しいセッションでは worktree が残らないので、中断するときは差分をパッチにして残す（6 章）。
